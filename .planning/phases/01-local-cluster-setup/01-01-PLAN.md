# Plan 01-01: Local Kubernetes Cluster Setup with kind

## Overview
Establish a lightweight, single-node `kind` (Kubernetes in Docker) local cluster named `msb-ecom-local` tailored for the resource constraints of an i5 laptop (15GB RAM). The cluster configuration includes host port mappings (`extraPortMappings`) allowing the host browser and curl commands to directly access the API Gateway, Frontend, and other entrypoints without complex ingress controllers.

## Tasks

<task id="01-01-01">
<title>Verify and install kind & kubectl client tooling</title>
<read_first>
- .planning/PROJECT.md
</read_first>
<action>
1. Check if `kind` and `kubectl` exist on PATH.
2. If missing, install standard Linux x86_64 binary releases into `~/.local/bin/` (which is in PATH):
   - For `kind`: download latest release binary (v0.27.0 or v0.24.0+) via curl, chmod +x to `~/.local/bin/kind`.
   - For `kubectl`: download latest stable release binary (v1.32.x) via curl, chmod +x to `~/.local/bin/kubectl`.
3. Verify `kind version` and `kubectl version --client` execute successfully.
</action>
<acceptance_criteria>
- `kind version` exits 0 and prints version string
- `kubectl version --client` exits 0 and prints client version string
</acceptance_criteria>
<verify>
kind version && kubectl version --client
</verify>
</task>

<task id="01-01-02">
<title>Author kind cluster configuration with port mappings</title>
<read_first>
- .planning/PROJECT.md
- .planning/REQUIREMENTS.md
</read_first>
<action>
1. Create `k8s/` directory if it does not exist.
2. Author `k8s/kind-cluster-config.yaml` specifying:
   - `kind: Cluster`
   - `apiVersion: kind.x-k8s.io/v1alpha4`
   - Single node with `role: control-plane`
   - `extraPortMappings` for host reachability:
     - `containerPort: 30000` -> `hostPort: 9000` (API Gateway NodePort)
     - `containerPort: 30080` -> `hostPort: 80` (Frontend NodePort)
     - `containerPort: 30420` -> `hostPort: 4200` (Frontend Dev NodePort)
     - `containerPort: 30850` -> `hostPort: 8085` (Auth / Keycloak NodePort if needed)
</action>
<acceptance_criteria>
- `k8s/kind-cluster-config.yaml` exists and is valid YAML
- File includes `role: control-plane` and `extraPortMappings` for ports 9000, 4200, 80
</acceptance_criteria>
<verify>
test -f k8s/kind-cluster-config.yaml
</verify>
</task>

<task id="01-01-03">
<title>Create and verify msb-ecom-local kind cluster</title>
<read_first>
- k8s/kind-cluster-config.yaml
</read_first>
<action>
1. Check if `msb-ecom-local` cluster already exists (`kind get clusters`).
2. If already exists and healthy, reuse it; otherwise create it using:
   `kind create cluster --name msb-ecom-local --config k8s/kind-cluster-config.yaml`
3. Set kubectl context to `kind-msb-ecom-local`.
4. Wait for node to become `Ready`:
   `kubectl wait --for=condition=Ready node --all --timeout=120s`
5. Verify cluster health:
   `kubectl cluster-info`
   `kubectl get nodes -o wide`
</action>
<acceptance_criteria>
- `kind get clusters` contains `msb-ecom-local`
- `kubectl get nodes` returns `msb-ecom-local-control-plane` in `Ready` status
- `kubectl cluster-info` returns Kubernetes control plane endpoint
</acceptance_criteria>
<verify>
kubectl get nodes | grep "Ready"
</verify>
</task>

## Verification
- Run `kind get clusters` to confirm `msb-ecom-local` is listed.
- Run `kubectl cluster-info` to confirm communication with the local API server.
- Run `kubectl get nodes` to verify the single node is `Ready`.
