# Plan 02-01: Microservices Containerization & Kind Image Loading

## Overview
Build optimized, multi-stage Docker container images for all 7 Spring Boot microservices and the Angular frontend, then load them directly into the `msb-ecom-local` `kind` cluster node runtime. This eliminates the need for a remote container registry and ensures immediate availability for local Kubernetes deployment.

## Tasks

<task id="02-01-01">
<title>Verify and optimize Dockerfiles across all microservices and frontend</title>
<read_first>
- api-gateway/Dockerfile
- auth-service/Dockerfile
- inventory-service/Dockerfile
- notification-service/Dockerfile
- order-service/Dockerfile
- payment-service/Dockerfile
- product-service/Dockerfile
- frontend/Dockerfile
</read_first>
<action>
1. Inspect each Dockerfile to ensure:
   - Java microservices: Multi-stage build with `eclipse-temurin:21-jdk` (builder) and `eclipse-temurin:21-jre-alpine` (runtime), non-root user `spring:spring`.
   - Frontend: Multi-stage build with `node:20-alpine` (builder) and `nginx:alpine` (runtime), SPA routing configured.
2. Confirm build contexts and jar artifact naming match target outputs.
</action>
<acceptance_criteria>
- All 8 Dockerfiles exist and follow multi-stage build patterns
- All runtime stages use lightweight base images (alpine/jre-alpine)
</acceptance_criteria>
<verify>
test -f api-gateway/Dockerfile && test -f frontend/Dockerfile
</verify>
</task>

<task id="02-01-02">
<title>Build all 8 container images with local tags</title>
<read_first>
- .planning/PROJECT.md
</read_first>
<action>
1. Build local container images tagged under `msb-ecom/`:
   - `docker build -t msb-ecom/api-gateway:local ./api-gateway`
   - `docker build -t msb-ecom/auth-service:local ./auth-service`
   - `docker build -t msb-ecom/product-service:local ./product-service`
   - `docker build -t msb-ecom/order-service:local ./order-service`
   - `docker build -t msb-ecom/inventory-service:local ./inventory-service`
   - `docker build -t msb-ecom/payment-service:local ./payment-service`
   - `docker build -t msb-ecom/notification-service:local ./notification-service`
   - `docker build -t msb-ecom/frontend:local ./frontend`
2. Verify all 8 images exist in the local Docker daemon.
</action>
<acceptance_criteria>
- `docker images | grep msb-ecom/` returns all 8 images with tag `local`
</acceptance_criteria>
<verify>
docker images --format '{{.Repository}}:{{.Tag}}' | grep "msb-ecom/" | wc -l
</verify>
</task>

<task id="02-01-03">
<title>Load container images into msb-ecom-local kind cluster</title>
<read_first>
- k8s/kind-cluster-config.yaml
</read_first>
<action>
1. Verify `kind` cluster `msb-ecom-local` is running.
2. Load all 8 images into the kind cluster:
   `kind load docker-image --name msb-ecom-local \
     msb-ecom/api-gateway:local \
     msb-ecom/auth-service:local \
     msb-ecom/product-service:local \
     msb-ecom/order-service:local \
     msb-ecom/inventory-service:local \
     msb-ecom/payment-service:local \
     msb-ecom/notification-service:local \
     msb-ecom/frontend:local`
3. Verify images are present in the kind node runtime (`crictl images`).
</action>
<acceptance_criteria>
- `docker exec -it msb-ecom-local-control-plane crictl images | grep msb-ecom` shows all 8 images loaded
</acceptance_criteria>
<verify>
docker exec msb-ecom-local-control-plane crictl images | grep "msb-ecom" | wc -l
</verify>
</task>

## Verification
- Run `docker images | grep msb-ecom` to verify local Docker builds.
- Run `docker exec msb-ecom-local-control-plane crictl images | grep msb-ecom` to verify cluster node image cache.
