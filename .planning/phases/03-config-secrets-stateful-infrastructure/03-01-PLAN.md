# Plan 03-01: Config, Secrets & Stateful Infrastructure Deployment

## Overview
Establish the foundational infrastructure layer in Kubernetes for `msb-ecom`. This includes creating the `msb-ecom` namespace, central ConfigMaps & Secrets, stateful databases (MongoDB, MySQL, PostgreSQL for Auth & Keycloak), Mailpit, Keycloak, and Apache Kafka. All services will be exposed via Kubernetes `ClusterIP` Services with persistent volume storage backed by kind's default local-path storage class.

## Tasks

<task id="03-01-01">
<title>Create namespace, ConfigMaps, and Secrets manifests</title>
<read_first>
- docker-compose.yml
- docker-compose.prod.yml
</read_first>
<action>
1. Author `k8s/00-namespace.yaml` defining namespace `msb-ecom`.
2. Author `k8s/01-configmaps-secrets.yaml` containing:
   - ConfigMap `app-config`: DB hosts, ports, URLs, Kafka bootstrap (`broker:29092` / `kafka:9092`), Mailpit host.
   - Secret `app-secrets`: MySQL root password, Postgres user/pass, Mongo credentials, JWT secret, Keycloak admin credentials.
3. Apply manifests to cluster:
   `kubectl apply -f k8s/00-namespace.yaml`
   `kubectl apply -f k8s/01-configmaps-secrets.yaml`
</action>
<acceptance_criteria>
- Namespace `msb-ecom` exists
- ConfigMap `app-config` and Secret `app-secrets` are applied in `msb-ecom`
</acceptance_criteria>
<verify>
kubectl get ns msb-ecom && kubectl get configmap,secret -n msb-ecom
</verify>
</task>

<task id="03-01-02">
<title>Author and deploy stateful databases (PostgreSQL, MongoDB, MySQL)</title>
<read_first>
- docker-compose.yml
</read_first>
<action>
1. Author `k8s/02-databases.yaml` defining Deployments, PVCs (1Gi each), and ClusterIP Services for:
   - `mongo` (port 27017, PVC `mongo-pvc`)
   - `mysql` (port 3306, PVC `mysql-pvc`, with init container or config to create `order_service`, `inventory_service`, `payment_service` databases)
   - `postgres-auth` (port 5432, PVC `postgres-auth-pvc`, DB `auth_service`)
   - `postgres-keycloak` (port 5432, PVC `postgres-keycloak-pvc`, DB `keycloak`)
2. Apply `k8s/02-databases.yaml` to `msb-ecom` namespace:
   `kubectl apply -f k8s/02-databases.yaml`
3. Wait for all database pods to reach `Ready` status.
</action>
<acceptance_criteria>
- Pods `mongo`, `mysql`, `postgres-auth`, and `postgres-keycloak` reach `Running` & `Ready`
- PVCs are bound
- Services `mongo`, `mysql`, `postgres-auth`, `postgres-keycloak` exist
</acceptance_criteria>
<verify>
kubectl get pods -n msb-ecom -l app.kubernetes.io/tier=database
</verify>
</task>

<task id="03-01-03">
<title>Author and deploy Kafka, Keycloak, and Mailpit infrastructure</title>
<read_first>
- docker-compose.yml
- docker-compose.prod.yml
</read_first>
<action>
1. Author `k8s/03-infrastructure.yaml` defining:
   - `zookeeper` + `broker` (or KRaft Kafka) with ClusterIP Service `broker` (port 9092, 29092)
   - `keycloak` (quay.io/keycloak/keycloak:24.0.1) connecting to `postgres-keycloak`, ClusterIP Service `keycloak` (port 8080)
   - `mailpit` (axllent/mailpit) with ClusterIP Service `mailpit` (SMTP 1025, Web 8025)
2. Apply `k8s/03-infrastructure.yaml`:
   `kubectl apply -f k8s/03-infrastructure.yaml`
3. Wait for Kafka, Keycloak, and Mailpit pods to reach `Ready`.
</action>
<acceptance_criteria>
- `broker`, `zookeeper` (or KRaft), `keycloak`, and `mailpit` pods are `Running` & `Ready`
- Services are resolvable in the `msb-ecom` namespace
</acceptance_criteria>
<verify>
kubectl get pods -n msb-ecom -l app.kubernetes.io/tier=infrastructure
</verify>
</task>
