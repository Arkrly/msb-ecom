# Plan 04-01: Backend Services, Gateway Routing & Frontend Deployment

## Overview
Deploy all 6 backend Spring Boot microservices (Auth, Product, Order, Inventory, Payment, Notification), the API Gateway, and the Angular Frontend into the `msb-ecom` Kubernetes namespace. Configure Spring Actuator `/actuator/health` liveness and readiness probes, bounded resource requests/limits, and NodePort exposure for direct host machine reachability.

## Tasks

<task id="04-01-01">
<title>Author and deploy backend microservices with Actuator health probes</title>
<read_first>
- docker-compose.prod.yml
- k8s/01-configmaps-secrets.yaml
</read_first>
<action>
1. Author `k8s/04-backend-services.yaml` defining Deployments and ClusterIP Services for:
   - `auth-service` (port 8085, Postgres datasource, JWT secret, Actuator probe)
   - `product-service` (port 8080, Mongo URI, Actuator probe)
   - `order-service` (port 8081, MySQL datasource, Kafka broker, Actuator probe)
   - `inventory-service` (port 8082, MySQL datasource, Actuator probe)
   - `payment-service` (port 8084, MySQL datasource, Actuator probe)
   - `notification-service` (port 8083, Kafka broker, Mailpit SMTP, Actuator probe)
2. Include standard probe definitions:
   - `livenessProbe`: HTTP GET `/actuator/health/liveness`, initialDelay 30s, period 10s
   - `readinessProbe`: HTTP GET `/actuator/health/readiness`, initialDelay 20s, period 5s
3. Apply `k8s/04-backend-services.yaml`:
   `kubectl apply -f k8s/04-backend-services.yaml`
4. Wait for all 6 backend pods to reach `Ready`.
</action>
<acceptance_criteria>
- All 6 backend service Deployments and Services exist in `msb-ecom`
- All 6 backend service pods pass Actuator readiness probes and reach `Running (1/1)`
</acceptance_criteria>
<verify>
kubectl get pods -n msb-ecom -l app.kubernetes.io/tier=backend
</verify>
</task>

<task id="04-01-02">
<title>Author and deploy API Gateway and Angular Frontend with NodePort routing</title>
<read_first>
- k8s/kind-cluster-config.yaml
- docker-compose.prod.yml
</read_first>
<action>
1. Author `k8s/05-gateway-frontend.yaml` defining:
   - `api-gateway`:
     - Deployment targeting `msb-ecom/api-gateway:local`
     - Env vars: backend service URLs (`http://product-service:8080`, `http://order-service:8081`, etc.)
     - Actuator liveness/readiness probes
     - NodePort Service with `nodePort: 30000` (port 9000)
   - `frontend`:
     - Deployment targeting `msb-ecom/frontend:local`
     - Nginx HTTP probe on `/`
     - NodePort Service with `nodePort: 30080` (port 80) and `nodePort: 30420` (port 4200)
2. Apply `k8s/05-gateway-frontend.yaml`:
   `kubectl apply -f k8s/05-gateway-frontend.yaml`
3. Wait for `api-gateway` and `frontend` pods to reach `Ready`.
</action>
<acceptance_criteria>
- `api-gateway` NodePort Service exposed on 30000
- `frontend` NodePort Service exposed on 30080 / 30420
- Both pods are `Running (1/1)`
- Host `http://localhost:9000/actuator/health` and `http://localhost:4200/` are reachable
</acceptance_criteria>
<verify>
curl -sf http://localhost:9000/actuator/health && curl -sf http://localhost:4200/ > /dev/null
</verify>
</task>
